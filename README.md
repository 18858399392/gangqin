# NOCTURNE · 夜曲

A buildless, viewport-filling piano/guitar lesson player. Serve `dist/` with a static web server.

The page opens on 樱花草 in a close piano view and attempts audible playback and native fullscreen. Browsers that require a gesture show one small start control. Clicking it resumes the AudioContext and retries the Fullscreen API. The application view fills the viewport independently of native fullscreen support.

The main screen contains song/instrument/menu pills, a compact transport and the instrument. Songs, favorites, playback speed, left/right piano parts, stepwise audition, A–B looping, metronome, free strumming, camera, labels, zoom, volume and credits live in nested menu pages. There is no landing-page introduction.

`scene.js` renders beveled ivory/ebony keys, reflective lacquer, studio lighting, incoming notes, actual key depressions and a closely framed rosewood fingerboard with metallic strings and frets. The guitar view follows high positions. The same event data drives the audio, note readout and physical string/fret markers. Keys and fret positions can be played with pointer input. A Canvas fallback keeps lessons usable without WebGL.

`music.js` annotates 樱花草's piano staves using its original two velocity-coded voices; other piano scores use an approximate split by register. Guitar arrangements use standard E2–A2–D3–G3–B3–E4 tuning, a beam search for unique string assignments in frets 0–12, no more than four frets of hand span and four distinct pressed fret positions, and consistent single-string note releases. Some voices move octaves or are reduced to make the arrangement playable; these are site-specific simplified arrangements, not an authoritative artist fingering. The displayed string plus fret equals the MIDI pitch that sounds.

Audio: twenty locally bundled Salamander piano samples (Alexander Holm, CC BY 3.0) and thirteen acoustic guitar recordings (University of Iowa, edited/distributed by Nicholas Brosowsky in tonejs-instruments, CC BY 3.0). Source links and attribution are retained in the secondary information page and `dist/assets/guitar/ATTRIBUTION.txt`. Three.js retains its MIT license header. The 樱花草 piano arrangement was transcribed from the linked 37-bar EOP score.

Validated: syntax and local assets; DOM interaction and AudioContext mocks for allowed/blocked autoplay, nested menus, default song, instrument switching, half-speed clock, hand filtering, step audition, A–B loops, strumming, favorites and settings; finite 3D geometry, camera projections on desktop and 844×390 landscape, key and guitar raycast pitch mapping; every bundled guitar arrangement's string/fret pitch, uniqueness, and hand span. A connected browser was unavailable, so real GPU output, device fullscreen behavior and speaker output are not verified.

The mobile shell now always uses landscape dimensions. Where available, a fullscreen gesture also requests `screen.orientation.lock('landscape')`. When the device/browser refuses orientation lock, a rotated layout uses the portrait screen as a landscape canvas; custom piano/fretboard hit tests invert that transform. The secondary sheet remains inside the transformed shell, uses an ordinary dialog with a separate scrim, traps focus, and closes with Escape. A physical rotation removes the software transform.

The visual refinement uses a perspective camera, studio ground/shadows, pearl-finish keys, champagne trim, textured rosewood, mother-of-pearl fret inlays, thick rounded note gems with pearl highlights, and a small reusable particle pool. Star feedback can be disabled in settings and respects reduced-motion preferences. The Canvas compatibility painter also has shaded key edges, rounded colored note capsules, wood grain, metallic strings and restrained sparkles. Canvas preview images were rendered and inspected locally; this is separate from browser/GPU verification.

Desktop keyboard input follows the Virtual Piano C2–C7 letter-sheet layout (36 white keys across 1–0, Q–P, A–L, Z–M; Shift plays the corresponding sharps). The exact diagram is linked from https://virtualpiano.net/how-to-play/. Guitar uses Musicca's actual English layout, verified from https://www.musicca.com/files/scripts/virtual-guitar/translation/English.js: number/Q/A/Z rows are strings 3/4/5/6, with Shift+number/Q for strings 1/2. First keys are open strings. The bottom row covers 0–9 and other rows 0–11; a site extension moves the fret origin 0–3 using PageUp/PageDown or the secondary keyboard menu. This is a common existing layout, not an industry-wide standard. Letter-sheet links and full current maps live in the keyboard menu, while actual note names and string/fret readings remain visible for real-instrument learning.

Keyboard held notes are polyphonic, release on keyup, and clear on blur, hidden tabs, menu opening, transport changes and instrument switches. Repeated keydown, IME composition, editing fields and browser shortcuts are ignored. The hardware's key rollover still limits simultaneous key combinations. Hints default on for mouse/desktop and off for coarse touch, and can be toggled independently of note labels.

Keyboard validation: all 61 piano pitches are contiguous and have unique bindings; all 70 guitar bindings were compared with Musicca's official English configuration. Event/AudioContext mocks exercise simultaneous piano notes, guitar same-string damping, keyup and Shift transitions, repeat suppression, early release during async audio initialization, menu and editable-field isolation, blur cleanup, hint preferences and fret-origin changes. Both actual Canvas painters were previewed with keyboard labels; the 3D scene checks also run with hints and held notes enabled. Real browser audio/keyboard latency and hardware rollover have not been measured.
