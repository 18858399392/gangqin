# NOCTURNE · 夜曲

A buildless piano/guitar learning player. Serve `dist/` as a static site; `.openai/hosting.json` retains its Sites project identity.

Production: [gangqin.kanglimin.com](https://gangqin.kanglimin.com/), hosted directly on Cloudflare Workers Static Assets. The source is on GitHub at [18858399392/gangqin](https://github.com/18858399392/gangqin). The final item in the main menu, 联系与反馈, opens `https://kanglimin.com/` in a separate tab.

`wrangler.toml` serves `dist/` directly and binds the requested custom domain. No dependency installation or build step is required. After Cloudflare authentication, deploy with `npx wrangler@4.151.3 deploy`; Wrangler manages the custom-domain route and its DNS record. For a remote/container login, use `npx wrangler@4.151.3 login --device --browser=false`. GitHub remote `github` is the canonical source; `origin` and `.openai/hosting.json` retain the former private Sites preview. `vercel.json` is retained for the earlier temporary preview and does not control Cloudflare production hosting.

## Playback and modes

The page selects 樱花草 and attempts audible autoplay and native fullscreen. There is no central start button. When the browser allows audio, the score starts from the beginning after local samples are ready. When autoplay is blocked, the score and instrument still animate using a silent performance clock. A small status in the transport explains that a normal interaction can enable sound. Pointer/click/keyboard interaction retries audio and fullscreen where supported; audio joins the displayed score position. Intentional pause, manual play and menu actions cancel stale asynchronous requests. Browser autoplay policy still governs whether the first visit may produce sound without interaction.

Demonstration and step-by-step learning display real note names (C2, D2, C4) and guitar string/fret numbers. Computer shortcut labels appear only in free play, including when typing a note switches to manual play. The keyboard menu can disable these labels. Piano follows Virtual Piano's C2–C7 letter-sheet mapping, with Shift for black keys; guitar uses Musicca's official English mapping (number/Q/A/Z rows are strings 3/4/5/6, Shift+number/Q are strings 1/2). The first key of each row is an open string. PageUp/PageDown can shift the guitar fret origin 0–3. All 61 piano pitches and all 70 base guitar bindings were checked against the sources. Keyboard voices support polyphony, keyup release, same-string damping and cleanup on blur, hidden tabs, menus and mode changes.

Sources: https://virtualpiano.net/how-to-play/ and https://www.musicca.com/files/scripts/virtual-guitar/translation/English.js. These are established layouts, not an industry-wide standard.

## Interface and lessons

The main view contains compact song, instrument and menu controls and a transport. A sun/moon button immediately left of the menu switches day/night styling, scene lighting and the browser theme color; the existing settings switch stays synchronized. The transport shows a compact sequence/single toggle. Sequential playback is the default: finishing a score automatically starts the next one in catalog order, wrapping to the first at the end. Single mode repeats the current score. Manual previous/next still changes songs in either mode; A–B loops take precedence. Automatic advances retain open menus and keyboard focus and do not request fullscreen again. The main menu provides songs, practice, free play, About, settings and keyboard maps. About is directly alongside settings and contains six collapsible beginner chapters covering note/octave labels, piano keys, guitar strings/frets, rhythm/harmony and a first 樱花草 practice routine. Inline piano and fretboard diagrams have accessible titles. Secondary pages retain their return path and disclosure state, with keyboard focus trapping.

The bottom arrows, keyboard Left/Right and media previous/next actions switch complete songs, wrapping through the score library. Group navigation/audition lives in the Practice submenu. Song import is intentionally deferred.

Practice supports speed changes without transposition, piano hand filtering, manual group stepping/audition, A–B loops and a metronome. The mobile shell uses landscape dimensions. Detection combines mobile UA/client hints, touch/pointer capabilities, small-screen dimensions and narrow portrait viewports, including embedded browsers that report desktop input settings. If native orientation lock is unavailable, the entire shell is rotated to fill the viewport and hit coordinates are corrected; physical rotation removes the software transform. The stage is absolutely sized inside the shell so portrait viewport dimensions cannot shrink the instrument canvas. Phone navigation hides the English wordmark and uses distinct grid cells for the song, instrument selector and theme/menu actions; long song titles ellipsize. The menu stays inside the transformed shell.

## Scene and sound

`scene.js` renders a close photographic instrument view using Three.js r170/WebGL2. The original Blender-generated GLB library (`scripts/build-instrument-models.py`) contains seven shouldered white-key profiles, tapered black keys, rounded lacquer case profiles, a radiused fingerboard, a D-profile wooden neck and a six-slotted nut. Each piano key remains a separately raycastable, physically depressed pivot. The keys have real dark separation gaps and fine manufactured bevels; their nonmetallic satin resin/ebony materials differ from the black clearcoat case. There is no gold piano frame or falling-note animation. The existing pastel surface light and small ripple are clipped to each actual key profile and respect effects/reduced-motion settings.

`realism.js` loads locally hosted Poly Haven CC0 wood color/normal/roughness maps and the Studio Small 09 photographic HDR environment, with a local studio reflection fallback. The HDR is prefiltered with PMREM; neutral key/fill/rim lighting and a quiet floor replace the decorative rings and purple backdrop. The wood source is a stained tabletop scan, tinted for the fingerboard, not a species-authenticated rosewood scan. Original URLs, authors, licenses and hashes are retained in `assets/materials/SOURCES.json` and the secondary credits page. Three.js addons retain the MIT license in `assets/THREE-LICENSE.txt`.

The guitar has exactly six differently sized strings, winding detail on bass strings, low rounded fret crowns following the fingerboard radius and restrained pearl position dots. Cyan/peach contact markers sit just behind the selected fret wire; faint rings preview the next positions. String vibration decays from the current nut/fret boundary and can be disabled. String/fret pitches still come from the existing standard-tuning arrangement; some voices move octaves or are reduced, and this does not assert an artist's authoritative fingering. Source piano staff hands remain in event data.

The camera remains fixed throughout each score. Piano framing is calculated from the complete song range; guitar framing includes frets 0–12. Note changes, seeking and swiping never pan or zoom the camera. Close/overhead views and zoom remain available. Initial pixel ratio is capped at 1.35 on small screens and 1.75 on desktops, with 1024/2048 shadows respectively. The model library is approximately 470KB and the CC0 image/HDR assets total about 2.1MB; geometry/environment load progressively without blocking the score or local audio. A Canvas teaching view remains for devices without WebGL2.

Audio uses 20 local Salamander piano samples (Alexander Holm, CC BY 3.0) and 13 acoustic guitar samples (University of Iowa, edited/distributed by Nicholas Brosowsky, CC BY 3.0). Attribution and score sources remain in the secondary information page and asset attribution file. Three.js retains its MIT header.

## Guitar string interaction

Guitar strings use a shared damped fixed-end modal model in WebGL and Canvas. Manual contact bends the selected string; release excites three decaying modes. The nut/current fret remains a vibration boundary. Low/high strings and fret positions vary the visible response; visual oscillation is slowed for readability while audio keeps its real pitch. Automatic notes, computer keys and repeated manual plucks excite the same motion.

Pointer capture supports multiple simultaneous contacts and interpolates every crossed string during a fast sweep. Sweep speed controls note velocity and vibration amplitude. Manual input pauses the demo once, allowing adjacent strings to ring together; retriggering the same string damps its former voice. Audio unlock starts on contact, visual feedback starts before sample loading completes, and cancellation/menu/instrument/visibility changes clear held gestures. The camera remains fixed. Reduced-motion and disabled effects suppress displacement.
